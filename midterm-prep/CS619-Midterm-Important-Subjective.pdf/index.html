  1. What is CS619? Who can select it and when?
    Topic: Project Overview and Selection

    CS619 is the Final Project course of Virtual University of Pakistan. It is the degree-completion project in which a student selects a real software project from the announced project list and develops it step by step under the supervision of a project supervisor. A BS (CS/IT/SE) student can select CS619 in the 7th semester after completing at least 90 credit hours, while an MCS/MIT student can select it in the 3rd semester after completing at least 30 credit hours. If the required credit hours are not complete, the student cannot select the project.

  2. Describe the steps of selecting a project in CS619.
    Topic: Project Overview and Selection

    A student selects the project through the following steps: (1) In course selection, the CS619 course code appears only for students whose credit hours are complete, and the student selects it. (2) After about one week, a project list (Word file) is announced in the CS619 announcements on the LMS, containing project names, details and a selection button. (3) The student views the projects and submits a selection request for the desired project. (4) The student must keep checking the LMS and email, because the instructor may not accept the request if the seats of that project are full. (5) After about two weeks, the CS619 subject finally appears in the student's LMS and the project work starts under the assigned supervisor.

  3. What are the main project domains/categories offered in CS619? Give the tools used in each.
    Topic: Project Overview and Selection

    The main project domains/categories offered in CS619 are: (1) Web-based applications, e.g. online examination systems, job portals and management systems, developed with PHP, HTML, CSS, JavaScript and MySQL. (2) Android (mobile) applications, developed with Java in Android Studio using Firebase database. (3) Desktop applications, developed with C# and SQL Server in Visual Studio. (4) Game development projects using Unity. (5) Networking projects. A student should select the domain according to his/her interest and the field in which he/she wants to build a career.

  4. What is a project proposal? Write its main contents.
    Topic: Project Overview and Selection

    A project proposal is the initial document that describes what project the student intends to develop. Its main contents are: project title, project domain/category, introduction and background, problem statement, objectives of the project, scope of the project, the tools and technologies to be used (languages, database, software), and the expected deliverables. The proposal helps the supervisor judge whether the project is feasible and suitable before the actual work begins.

  5. Describe the four deliverables (assignments) of CS619 in order.
    Topic: Project Overview and Selection

    The four deliverables of CS619, in order, are: (1) SRS (Software Requirements Specification) — the document containing the complete requirements of the selected project, prepared with word processing and diagram tools. (2) Design Phase (DP) — the design document containing different UML diagrams of the project, prepared using UML/Visio tools. (3) Test Phase — a small and tough programming task related to the project, along with an online viva (through Skype). (4) Final Deliverable — the complete working project together with its full documentation and a presentation, evaluated through viva. Each deliverable is submitted on the LMS by its due date and is graded by the supervisor.

  6. What is an SRS? Write the main contents of an SRS document.
    Topic: SRS — Software Requirements Specification

    SRS stands for Software Requirements Specification. It is a document that describes in detail what the system should do. It is prepared in the requirement gathering and analysis phase and acts as an agreement between the customer and the developer; all later design and development work is based on it. Main contents of an SRS are: introduction (purpose, scope, definitions and references), overall description (product perspective, product functions, user characteristics), functional requirements of the system, non-functional requirements (performance, security, reliability etc.), use case diagrams and use case descriptions, and the external interface requirements (user, hardware and software interfaces).

  7. Differentiate between functional and non-functional requirements. Give two examples of each.
    Topic: SRS — Software Requirements Specification

    Functional requirements describe the functions and services the system must provide, i.e. what the system should do. Examples: the system shall allow students to register online; the admin shall be able to delete user accounts; the system shall generate monthly sales reports. Non-functional requirements describe the qualities and constraints of the system, i.e. how the system should perform. Examples: the system shall respond to a query within two seconds; the system shall be available 24 hours a day; the system shall support 500 concurrent users. In short, functional requirements define the behaviour of the system, while non-functional requirements define its performance, security, reliability and usability characteristics.

  8. Write any five characteristics of a good SRS.
    Topic: SRS — Software Requirements Specification

    A good SRS should have the following characteristics: (1) Correct — every requirement stated is one that the software should actually meet. (2) Unambiguous — every requirement has only one interpretation. (3) Complete — it includes all significant functional and non-functional requirements. (4) Consistent — no requirement conflicts with any other requirement. (5) Verifiable — there is a practical way to check that the software meets each requirement. (6) Modifiable — its structure allows changes to be made easily. (7) Traceable — the origin of each requirement is clear and it can be followed through design and testing.

  9. What is requirement elicitation? Write any four techniques of gathering requirements.
    Topic: SRS — Software Requirements Specification

    Requirement elicitation is the process of gathering requirements from users and stakeholders. Common techniques are: (1) Interviews — direct discussion with the users and stakeholders. (2) Questionnaires — written sets of questions distributed to a large number of users. (3) Observation — watching the users while they perform their routine work in the existing system. (4) Document analysis — studying the forms, reports and manuals of the existing system. (5) Brainstorming and workshops — group sessions to generate and discuss ideas. The gathered requirements are then analysed and documented in the SRS.

  10. What is UML? Write its three building blocks.
    Topic: Design Phase and UML

    UML (Unified Modeling Language) is a standard, general-purpose visual modeling language created by the Object Management Group (OMG). It is used to specify, visualize, construct and document the artifacts of a software system, and it is closely related to object-oriented analysis and design. UML is not a programming language; it is a pictorial language used to make software blueprints. The three building blocks of UML are: (1) Things — the basic elements of a model (structural, behavioral, grouping and annotational things). (2) Relationships — they show how the things are associated with each other, e.g. dependency, association, generalization and realization. (3) Diagrams — graphical views of the model, e.g. use case diagram, class diagram and sequence diagram.

  11. What is a Design Document? Write its main contents.
    Topic: Design Phase and UML

    The Design Document (DD) is the second deliverable of CS619, prepared in the design phase from the approved SRS. It describes how the system will be built. Its main contents are: system architecture, use case diagram, class diagram, sequence diagrams, activity/state diagrams where needed, the database design including the ER diagram and the table structures, and the interface (form/screen) designs. Tools such as MS Visio are used to draw these UML diagrams. The design document acts as a blueprint that is directly followed during coding.

  12. What is a use case diagram? Write its main components.
    Topic: Design Phase and UML

    A use case represents a user goal that can be achieved by accessing the system. The main components of a use case diagram are: (1) Actor — a role played by a user or any external system that interacts with the system; it is drawn as a stick figure outside the system boundary. (2) Use case — a set of actions performed by the system for a specific goal; it is drawn as an ellipse inside the boundary. (3) System boundary — a rectangle that encloses all the use cases of the system. (4) Relationships — association between actors and use cases, and include, extend and generalization relationships between use cases.

  13. Differentiate between INCLUDE and EXTEND relationships in a use case diagram.
    Topic: Design Phase and UML

    Include relationship: it specifies that the behavior of the included use case is always inserted into the behavior of the base use case; the base use case is incomplete without it. For example, 'Login' is included in 'Place Order' because every order requires login. Extend relationship: it specifies how the behavior of the extending use case can be inserted into the base use case only under specific conditions; the base use case is complete and meaningful on its own. For example, 'Apply Discount Coupon' extends 'Place Order' only when the customer has a valid coupon. In short, include is mandatory and always executed, while extend is optional and conditional.

  14. What is a class diagram? Describe the structure of a class in it.
    Topic: Design Phase and UML

    A class diagram is a static UML diagram that shows the structure of a system in terms of its classes, their attributes and operations, and the relationships among classes. It is the most important diagram used in application development and is drawn in the design phase. A class is represented by a rectangle divided into three compartments: the top compartment contains the class name, the middle compartment contains the attributes (data), and the bottom compartment contains the operations (methods). Relationships shown between classes include association, inheritance (generalization), aggregation and composition, along with multiplicities.

  15. What is a sequence diagram? Explain lifeline, activation and the types of messages.
    Topic: Design Phase and UML

    A sequence diagram is an interaction diagram that shows how objects interact with each other in chronological (time) order to carry out an operation or a use case. Its main elements are: (1) Objects/actors, placed at the top. (2) Lifeline — the vertical dashed line below an object representing its existence over time. (3) Activation — a thin rectangle on the lifeline showing the period during which the object performs an operation. (4) Messages — arrows between lifelines showing communication; types include call message (invokes an operation), return message (returns information to the caller), self-message (an object invokes its own operation), create message (creates a new object) and destroy message (ends the lifecycle of an object).

  16. Differentiate between structural things and behavioral things in UML.
    Topic: Design Phase and UML

    Structural things define the static part of a UML model; they represent the physical and conceptual elements of the system. Examples are class, interface, collaboration, use case, component and node. Behavioral things are the dynamic parts of a UML model; they represent the behavior of the system over time and space. Examples are interaction (a set of messages exchanged among elements to accomplish a task) and state machine (the sequence of states an object goes through in response to events). In short, structural things show what the system is made of, while behavioral things show what the system does.

  17. Explain the phases of the Waterfall model.
    Topic: Design Phase and UML

    The Waterfall model is the earliest SDLC model; it is a linear-sequential model in which each phase must be completed before the next phase begins and the phases do not overlap. Its phases are: (1) Requirement Gathering and Analysis — all requirements are captured and documented in the SRS. (2) System Design — the system design and overall architecture are prepared from the requirements. (3) Implementation — the system is developed in small units and each unit is unit tested. (4) Integration and Testing — all units are integrated and the whole system is tested. (5) Deployment — the product is deployed in the customer environment. (6) Maintenance — patches and improved versions are released to fix issues and enhance the product.

  18. Write the advantages and disadvantages of the Waterfall model.
    Topic: Design Phase and UML

    Advantages: it is simple and easy to understand and use; it is easy to manage because each phase has specific deliverables and a review process; phases are processed one at a time with clearly defined stages and well understood milestones; it works well for smaller projects where requirements are well understood. Disadvantages: no working software is produced until late during the life cycle; it cannot accommodate changing requirements; it has high risk and uncertainty; it is not a good model for complex, long and ongoing projects; integration is done as a big-bang at the very end.

  19. What is a DBMS? Write its advantages over a file processing system.
    Topic: Database Design and SQL

    DBMS (Database Management System) is a collection of interrelated data and a set of programs used to store, retrieve and manage that data in an easy and effective manner. Advantages over a traditional file processing system are: (1) No redundant data — redundancy is removed by normalization, which saves storage and improves access time. (2) Data consistency and integrity — data remains correct and consistent across the database. (3) Easy access to data through query languages like SQL. (4) Data security and controlled access for different users. (5) Backup, recovery and concurrent access by multiple users are properly managed.

  20. Define super key, candidate key, primary key, alternate key and foreign key.
    Topic: Database Design and SQL

    (1) Super Key — a set of one or more attributes that can uniquely identify a row in a table. (2) Candidate Key — a super key that has no redundant attributes, i.e. a minimal super key. (3) Primary Key — the column or group of columns selected from the candidate keys to uniquely identify every row; it cannot contain duplicate or NULL values. (4) Alternate Key — a candidate key that is capable of becoming the primary key but has not been selected as the primary key. (5) Foreign Key — a column of a table that points to the primary key of another table; it acts as a cross-reference between tables and enforces referential integrity. (6) Compound (Composite) Key — a primary key made of two or more columns. (7) Surrogate Key — an artificial key used to uniquely identify a row when the table has no natural primary key.

  21. Differentiate between a primary key and a foreign key.
    Topic: Database Design and SQL

    Primary key: it uniquely identifies each record in its own table; it must contain unique values and cannot contain NULL values; a table can have only one primary key. Foreign key: it is a column of a table that refers to the primary key of another table; it acts as a cross-reference between the two tables and is used to establish relationships and enforce referential integrity; it can contain duplicate values and may allow NULL values; a table can have more than one foreign key. Example: in the Student table, Roll_No is the primary key; in the StudentCourse table, Roll_No is a foreign key referring to the Student table.

  22. What is an ER diagram? Write its main components and the symbols used for them.
    Topic: Database Design and SQL

    An ER (Entity Relationship) diagram is a graphical representation of the logical structure of a database; it shows the entities of a system and the relationships among them. The ER model was proposed by Peter Chen in 1971. The main components of an ER diagram are: (1) Entity — a real-world object; it is represented by a rectangle. (2) Attribute — a property of an entity; it is represented by an oval (ellipse). A multivalued attribute is shown by a double oval and a derived attribute by a dashed oval. (3) Relationship — an association between entities; it is represented by a diamond. ER diagrams are used as a blueprint for implementing the database; they can be translated into relational tables.

  23. Explain the four types of mapping cardinality in an ER model.
    Topic: Database Design and SQL

    Mapping cardinality (mapping constraints) expresses the number of entities of one entity set that can be associated with entities of another entity set through a relationship. Its four types are: (1) One to One — an entity of A can be associated with at most one entity of B, and an entity of B with at most one entity of A. (2) One to Many — an entity of A can be associated with any number of entities of B, while an entity of B can be associated with at most one entity of A. (3) Many to One — an entity of A can be associated with at most one entity of B, while an entity of B can be associated with any number of entities of A. (4) Many to Many — entities of A and B can each be associated with any number of entities of the other set.

  24. What is normalization? Why is it needed? Name the anomalies it removes.
    Topic: Database Design and SQL

    Normalization is the process of organizing data in a database to avoid data redundancy and the problems caused by it. It is needed because a badly designed (unnormalized) database suffers from three anomalies: (1) Insertion anomaly — certain data cannot be inserted into the table without the presence of other data. (2) Update anomaly — the same data is stored at multiple places, and updating it at one place but not at others makes the data inconsistent. (3) Deletion anomaly — deleting one record unintentionally deletes other useful data as well. Normalization removes redundancy by dividing data into related tables according to normal forms such as 1NF, 2NF, 3NF and BCNF.

  25. Differentiate between DDL, DML, DCL and TCL. Give two commands of each.
    Topic: Database Design and SQL

    (1) DDL (Data Definition Language) — used to define and modify the structure of database objects; commands: CREATE, ALTER, DROP. (2) DML (Data Manipulation Language) — used to access and manipulate the data stored in the database; commands: SELECT, INSERT, UPDATE, DELETE. (3) DCL (Data Control Language) — used to grant and revoke user access rights and permissions on the database; commands: GRANT, REVOKE. (4) TCL (Transaction Control Language) — used to save or undo the changes made by DML commands; commands: COMMIT (saves the changes permanently) and ROLLBACK (undoes the changes). In addition, SELECT is also treated as DQL (Data Query Language), used for querying data from the database.

  26. Differentiate between DELETE, DROP and TRUNCATE commands in SQL.
    Topic: Database Design and SQL

    DELETE: it removes rows from a table; if a WHERE clause is used, only the matching rows are removed, otherwise all rows are removed; the table structure remains intact and the operation can be rolled back. DROP: it deletes the entire table from the database; the table structure, indexes, privileges and constraints are also removed, and the operation cannot be rolled back. TRUNCATE: it removes ALL rows from a table, but the table structure, its columns, constraints and indexes remain; it is faster than DELETE and cannot be used with a WHERE clause.

  27. Differentiate between the WHERE clause and the HAVING clause in SQL.
    Topic: Database Design and SQL

    WHERE clause: it places conditions on the rows (selected columns) of a table and filters records before any grouping is done; it cannot be used with aggregate functions. HAVING clause: it places conditions on the groups created by the GROUP BY clause and filters group results; it is used with aggregate functions such as COUNT, SUM and AVG. The HAVING clause was added to SQL because the WHERE keyword cannot be used with aggregate functions. In a query, WHERE comes before GROUP BY, and HAVING comes after GROUP BY (and before ORDER BY if used).

  28. What is indexing in a database? Write its types.
    Topic: Database Design and SQL

    Indexing is a data structure technique used to efficiently retrieve records from the database files based on the attributes on which the index has been created. An index is a special lookup table that the database search engine uses to speed up data retrieval, just like the index at the back of a book. Types of indexes: (1) Primary Index — defined on an ordered data file whose key field is generally the primary key of the relation. (2) Secondary Index — generated from a field that is a candidate key with unique values, or a non-key field with duplicate values. (3) Clustering Index — defined on an ordered data file on a non-key (ordering) field.

  29. What is a stored procedure? Write its advantages.
    Topic: Database Design and SQL

    A stored procedure is a prepared SQL code that is saved in the database so that it can be reused over and over again. Instead of writing the same query repeatedly, the programmer simply calls the stored procedure to execute it. Parameters can also be passed to a stored procedure so that it acts according to the passed values. Advantages: it reduces repeated coding, improves performance because the code is pre-compiled and stored in the database, increases security by controlling access to data, and makes maintenance easier because a change is made at one place only.

  30. Which technologies are used in a web-based CS619 project? Also write the technologies used for Android and desktop projects.
    Topic: Project Technologies and Viva Preparation

    In a web-based CS619 project, the mandatory technologies are HTML, CSS, Bootstrap, PHP and MySQL. Front-end (client side) is developed with HTML (structure of pages), CSS and Bootstrap (styling and responsive design) and JavaScript (interactivity). Back-end (server side) is developed with PHP, and the database is MySQL. The local server package XAMPP provides Apache, MySQL and PHP for development and testing, and editors such as Notepad++ or Sublime Text are used for writing code. For Android projects, the technologies are Java with Android Studio and the Firebase database, while desktop projects commonly use C# with SQL Server in Visual Studio.

  31. How should a student prepare for the CS619 viva?
    Topic: Project Technologies and Viva Preparation

    The CS619 viva is conducted on the student's own project, so preparation should cover the complete project: (1) Know your SRS — the purpose, scope, functional and non-functional requirements of your project. (2) Know your Design Document — be able to explain every diagram you submitted, i.e. use case diagram, class diagram, sequence diagram and ER diagram. (3) Know your database — tables, primary and foreign keys, relationships and the SQL queries used in the project. (4) Know your code — the technologies used (e.g. PHP/MySQL for web projects), the flow of the main modules, and how forms, validation and sessions work. (5) Be ready to demonstrate the running project and to answer questions about any feature, its purpose and how it is implemented.
