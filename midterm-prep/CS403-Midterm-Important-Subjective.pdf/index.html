  1. What is the difference between a Database and a DBMS?

  20. Map the following: Real World Data, Metadata, Data Occurrences.

  27. How is a 1NF table converted into 2NF? Explain the process.
    Topic: Normalization

    The process for transforming a 1NF table to 2NF is: (i) Identify any determinants other than the composite key, and the columns they determine. (ii) Create and name a new table for each determinant and the unique columns it determines. (iii) Move the determined columns from the original table to the new table; the determinant becomes the primary key of the new table. (iv) Delete the columns you just moved from the original table, except for the determinant, which will serve as a foreign key. (v) The original table may be renamed to maintain semantic meaning. | Example from the source: CLASS (crId, stId, stName, fId, room, grade), with crId, stId -> stName, fId, room, grade; stId -> stName; crId -> fId, room. To remove the anomalies, the table is decomposed into three tables: STD (stId, stName), COURSE (crId, fId, room) and CLASS (crId, stId, grade). Now these three tables are in second normal form; there are no anomalies in this form, and we say this is 2NF.

  28. Convert the following relation into one normal form ahead (for example: if the relation is in 2nd normal form, convert it into 3rd normal form). Student (Student-ID, Student-Name, Father-Name, City, Hobby) with rows: (1, ABC, BC, Lahore, 'Cricket, Movies'), (2, DEF, EF, Islamabad, 'Football, Basketball'), (3, GHI, HI, Lahore, 'Movies, Body building'), (4, JKL, KL, Karachi, 'Cricket'). (Marks: 3)
    Topic: Normalization

    The given relation is not even in 1NF, because Hobby is a multivalued attribute — it contains more than one value in a single cell. One normal form ahead is 1NF, in which every attribute value must be atomic. The multivalued attribute is removed into a separate relation: Student (Student-ID, Student-Name, Father-Name, City) keeps one row per student, and a new relation StudentHobby (Student-ID, Hobby) holds one row per hobby: (1, Cricket), (1, Movies), (2, Football), (2, Basketball), (3, Movies), (3, Body building), (4, Cricket). Student-ID in StudentHobby is a foreign key referencing Student, and (Student-ID, Hobby) together form its key. Now all values are atomic, so the relations are in 1NF.

Find in which normal form the relation is, and also discuss how Update Anomalies would occur in the relation. (Marks: 5)
    Topic: Normalization

    The relation is in 2NF. All attribute values are atomic, so it is in 1NF; and since the primary key Course-ID is a single attribute, no non-key attribute can be partially dependent on part of the key, so it is also in 2NF. It is not in 3NF, because a transitive dependency exists: Course-ID -> Instructor-ID -> Instructor-Specialization, i.e. Instructor-Specialization depends on the key only through Instructor-ID. | Update anomaly: the specialization of an instructor is repeated in every course taught by that instructor — e.g. Instructor-ID 1 with specialization PQR appears in both course 101 and course 301. If the specialization of instructor 1 changes, the new value must be updated in every such row; if even one row is missed, the same instructor will appear with two different specializations and the database becomes inconsistent. This anomaly is removed by decomposing the relation into Course (Course-ID, Course-Title, Instructor-ID) and Instructor (Instructor-ID, Instructor-Specialization).

  74. What is Functional Dependency?
    Topic: Normalization

    A Functional dependency is denoted by X → Y between two sets of attributes X and Y that are subsets of R specifies a constraint on the possible tuple that can form a relation state r of R. The constraint is for any two tuples t1 and t2 in r if t1[X] = t2[X] then they have t1[Y] = t2[Y]. This means the value of X component of a tuple uniquely determines the value of component Y.

  75. What is Multivalued dependency?

    A relation schema R is in 2NF if it is in 1NF and every non-prime attribute A in R is fully functionally dependent on primary key.

  80. What is 3NF?
    Topic: Normalization

    A relation schema R is in 3NF if it is in 2NF and for every FD X→ A either of the following is true 1. X is a Super-key of R. 2. A is a prime attribute of R. In other words, if every non prime attribute is non-transitively dependent on primary key.

  81. What is BCNF (Boyce-Codd Normal Form)?
    Topic: Normalization

    A relation schema R is in BCNF if it is in 3NF and satisfies an additional constraint that for every FD X → A, X must be a candidate key.

  82. What is 4NF?
    Topic: Normalization

    A relation schema R is said to be in 4NF if for every Multivalued dependency X n Y that holds over R, one of following is true 1. X is subset or equal to (or) XY = R. 2. X is a super key.
