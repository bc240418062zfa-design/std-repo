  33. What is the difference between Margin and Padding?
    Topic: Layout, Panels, Transforms & Animation

    Margin and Padding are two very similar properties that are also related to an element's size. All Framework Elements have a Margin property, and all Controls (plus Border) have a Padding property. Their only difference is that Margin controls how much extra space gets placed around the outside edges of the element, whereas Padding controls how much extra space gets placed around the inside edges of the element. Both Margin and Padding are of type System.Windows.Thickness, a class that can represent one, two, or four double values. Margin permits negative values; Padding does not.

  50. Why should one care about the "Logical Tree"? Explain with one example. Also describe the logical tree of the code. (Marks: 3)
    Topic: Layout, Panels, Transforms & Animation

    The logical tree exists even if there is no XAML. Properties, events and resources are tied to logical trees. Properties are propagated down the tree and events can be routed up or down the tree, so one should care about it because it controls how property values and events flow through the application. Example: a property value set on a parent element in the logical tree (such as a Window) is propagated down to its child elements. The logical tree is a simplification of what's actually going on when rendered. The visual tree can be thought of as an extension of the logical tree, though some things can be dropped as well. The visual tree exposes visual implementation details, e.g. a ListBox is a border, two scrollbars and more. Only things from Visual or Visual3D appear in a visual tree. Avoid depending on the visual tree in your code.

  57. What are delegates? What are the uses of delegates?
    Topic: Events, Delegates & Event-Driven Programming

    A delegate is a reference to a method. It is like function pointers in some other languages. A delegate is a type that represents references to methods with a particular parameter list and return type; when you instantiate a delegate, you can associate its instance with any method with a compatible signature and return type, and you can invoke (or call) the method through the delegate instance. Uses: Delegates are used to define callback methods and implement event handling, and they are declared using the "delegate" keyword. You can declare a delegate that can appear on its own or even nested inside a class. Delegates allow you to develop libraries and classes that are easily extensible.

  61. Explain routed events.
    Topic: Events, Delegates & Event-Driven Programming

    Routed events are like dependency properties on top of .NET properties; similarly, routed events are a layer on top of .NET events. They can travel up or down a visual or logical tree. This helps apps remain oblivious to the visual tree. E.g. Button exposes Click based on MouseLeftButtonDown and KeyDown, but actually the button chrome or TextBlock visual child fires it; the event travels up the tree and the Button eventually sees it. Or, like in a previous example, a rectangle on top of a button: arbitrary complex content, but Click is still raised. Otherwise it would require custom code on the inner content or consumers. The concept is very similar to the dependency property concept.

  62. Name the three (3) routing strategies that can be chosen by each routed event when it is registered. (Marks: 3)
    Topic: Events, Delegates & Event-Driven Programming

    • Tunneling: The event is first raised on the root, then on each element down the tree until the source element is reached (or until the event is marked as handled). • Bubbling: The event is first raised on the source element, then on each element up the tree until the root is reached (or until the event is marked as handled). • Direct: The event is only raised on the source element. Only the source element is given the chance to invoke handlers in response.

  90. Write a note on the _cdecl calling convention.
    Topic: Windows Programming (Win32, GDI & C++)

    The cdecl is the default calling convention for C programs. In this calling convention, the stack is cleaned up by the caller. The cdecl calling convention creates larger executables than stdcall, because it requires each function call to include stack cleanup code.

  91. What is the difference between the stdcall and cdecl calling conventions?
    Topic: Windows Programming (Win32, GDI & C++)

    cdecl and stdcall just tell the compiler whether the called function or the calling function cleans up the stack. In the stdcall calling convention, the called function cleans up the stack when it is about to return, so if it is called in a bunch of different places, all of those calls do not need extra code to clean up the stack after the function call. In the cdecl calling convention, it is the caller function that is responsible for cleaning the stack, so every function call must also include extra code to clean up the stack after the function call.
