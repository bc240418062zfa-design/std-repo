  1. Define a system and an IT system.
    Topic: IT System and System Administration

    A system is a collection of elements or components that are organized for a common purpose. An IT system is a collection of computing and/or communications components and other resources that support one or more functional objectives of an organization.

  2. Name the six components of an IT system and briefly describe each one.
    Topic: IT System and System Administration

    The six components of an IT system are: (1) Computing Machines - the servers, workstations, desktops, laptops and mobile devices that do the actual work. (2) Software - operating systems, applications and utilities that run on the machines. (3) Network - routers, switches, firewalls, load balancers, cables, connectors and VPNs that connect everything. (4) Services - application services (such as web services) and network services (such as DNS and DHCP) provided to users. (5) Users - diverse people with different roles and different levels who use the system. (6) Processes - operations, support system, configurations and change management that keep the system running.

  3. How do the components of an IT system influence one another?
    Topic: IT System and System Administration

    The components of an IT system are integrated with each other and interact to produce a desired end result for the common objective of the organization. A change in one component influences the others: for example, the services an organization can offer depend on the computing machines, software and network available; the users and their roles determine the permissions, configurations and processes that must be managed; and the processes (installation, monitoring, change management) act on all other components to keep the whole system in its desired state. Because of this interdependence, a failure or change in any single component - hardware, software, network, services, users or processes - affects the working of the entire IT system.

  4. What is system administration? Who is a system administrator?
    Topic: IT System and System Administration

    System administration is the field of work which involves managing one or more systems - software, hardware, servers or workstations - with the objectives of efficiency and effectiveness. A system administrator is the person who looks after computers, networks, and the people who use them; he or she looks after hardware, operating systems, software, configurations, applications and security, and influences how effectively other people can use their computers and networks. System administrators are also known as network administrators, operators, system architects, system engineers and system programmers.

  5. List any five tasks or actions involved in managing an IT system.
    Topic: IT System and System Administration

    Managing an IT system means applying tasks and actions to the system. Any five of these are: (1) Installation and configuration of hardware and software. (2) Monitoring, logging and reporting on the system's state. (3) Changing the system, i.e. modifying it to bring it closer to its ideal (policy) state. (4) Supporting the users of the system. (5) Provisioning new machines, accounts and services. (6) Troubleshooting problems that arise in the system.

  6. Name the five states of a computer machine in Evard's life cycle and explain the Clean and Configured states.
    Topic: IT System and System Administration

    In Evard's life cycle, a computer machine passes through five states: New, Clean, Configured, Unknown and Off. Clean state: the machine has the operating system installed (through the build process - select OS, install OS, drivers and software) but it is not yet set up to function in the system. Configured state: the machine is properly configured to meet the needs of the system, with user roles and permissions set and updates applied and monitored through the update process.

  7. What is process maturity? List the five levels of the System Administration Maturity Model (SAMM) with their characteristics.
    Topic: IT System and System Administration

    Process maturity is a measure of how well defined and controlled a system's processes are; a high level of process maturity shows that processes are documented well, users understand and follow procedures, and there is continuous process improvement. The five SAMM levels are: Level 1 - Initial: ad hoc processes (fire fighting). Level 2 - Repeatable: disciplined process. Level 3 - Defined: standard, consistent process. Level 4 - Managed: predictable process. Level 5 - Optimizing: continuously improving process.

  8. Define reliability. How are reliability and failure probability calculated?
    Topic: Reliability and Availability

    Reliability is the probability that a system will perform its intended function(s) during a specified period of time under defined conditions. It is calculated as R(t) = Nw(t) / N(t0), where Nw(t) is the number of working systems at time t and N(t0) is the total number of systems at time t0. The failure probability is the complement of reliability: f(t) = Nnw(t) / N(t0) = 1 - R(t), where Nnw(t) is the number of failed systems at time t.

  9. Differentiate between MTTF and MTBF.
    Topic: Reliability and Availability

    MTTF (Mean Time To Failure) is the average time duration before a non-repairable system component fails, calculated as total functional hours divided by total units, and is equal to 1/lambda (failure rate). MTBF (Mean Time Between Failures) is the average time duration between inherent failures of a repairable system component, calculated as total functional hours divided by total failures. The two are related by MTBF = MTTF + MTTR, where MTTR is the mean time to recovery.

  10. What is availability? A component has MTBF of 200 hours and MTTR of 8 hours. Calculate its availability.
    Topic: Reliability and Availability

    Availability determines the instantaneous performance of a component at any given time, based on the time duration between its failure and recovery. It is calculated as: Availability = MTBF / (MTBF + MTTR). For the given component: Availability = 200 / (200 + 8) = 200 / 208 = 0.9615, i.e. approximately 96.15%.

  11. How are reliability and failure rate calculated for series-connected and parallel-connected components?
    Topic: Reliability and Availability

    For series-connected components, the system works only if all components work, so the overall reliability is the product of the individual reliabilities: R(t) = R1(t) x R2(t) x ... x Rn(t), and the effective failure rate is the sum of the failure rates of each component. For parallel-connected components, the system fails only if all components fail, so the overall reliability is R(t) = 1 - [(1 - R1(t)) x (1 - R2(t)) x ... x (1 - Rn(t))], and the MTTF is the reciprocal sum of the failure rates. Hybrid systems are first reduced to series or parallel configurations.

  12. Write any four advantages of Linux servers.
    Topic: Server Operating Systems

    Advantages of Linux servers include: (1) No additional licensing fee, as the operating system is free and open-source. (2) It is more reliable - it rarely experiences malware, cyber threats or other security errors. (3) It is not demanding on client hardware and has lower resource consumption, so it shows excellent performance rates due to its low infrastructure requirements. (4) System administrators have the freedom and opportunity to customize the system. (5) It allows seamless use of open-source software on the server and supports cooperative work without exposing the program's core.

  13. Write any four advantages of Windows servers.
    Topic: Server Operating Systems

    Advantages of Windows servers include: (1) It is beginner-friendly due to its intuitive graphical user interface and out-of-the-box functionality. (2) It comes with guaranteed five years of maintenance plus five years of extended support. (3) It supports third-party applications and is compatible with Microsoft applications. (4) It requires less admin monitoring and maintenance thanks to its robust approach and automated updates.

  14. Compare Linux and Windows server operating systems.
    Topic: Server Operating Systems

    Architecture: Linux is centered around the Linux kernel, while Windows is based on the Windows NT architecture. Cost: Linux is free and open-source, while Windows is owned by Microsoft and charges a licensing fee per user. Security: Linux is highly secure against malware and cyber threats, while Windows is more prone to hacking attempts and cyber threats. Operation and user experience: Linux is operated mainly through the command line and requires a relatively experienced administrator, while Windows offers a graphical user interface and is more beginner-friendly. Database support: Linux supports MySQL and PostgreSQL, while Windows supports Microsoft SQL Server and Microsoft Access. Scripting support: Linux supports Python, PHP, Perl and other Unix languages, while Windows supports ASP and ASP.NET. Support: Linux has large community support and great documentation, while Windows has community and long-term customer support.

  15. The root account is disabled by default in Ubuntu Server. How can a user carry out administrative tasks, and how can the root account be enabled if required?
    Topic: Ubuntu Server and Package Management

    In Ubuntu Server, the administrative root account is disabled by default: it has been given a password which matches no possible encrypted value, so it cannot log in directly. Instead, users are encouraged to use the tool sudo to carry out system administrative duties. sudo allows an authorized user to temporarily elevate their privileges using their own password instead of the root password; this provides accountability for all user actions and granular control over which actions a user can perform. By default, the initial user created by the installer is a member of the 'sudo' group, which is authorized in /etc/sudoers; any other account can be given full root access through sudo by adding it to the sudo group. If the root account must be enabled, simply give it a password with the command 'sudo passwd'. The root password can be disabled again with 'sudo passwd -l root'.

  16. Differentiate between dpkg and APT.
    Topic: Ubuntu Server and Package Management

    dpkg is a package manager for Debian-based systems. It can install, remove and build packages, but unlike other package management systems it cannot automatically download and install packages or their dependencies; it is used for local package files, e.g. 'sudo dpkg -i file.deb' installs a local .deb file and 'dpkg -l' lists installed packages. APT, used through the apt command, is a powerful command-line tool that works with Ubuntu's Advanced Packaging Tool: it performs installation of new software packages, upgrade of existing packages, updating of the package list index and upgrading of the entire Ubuntu system, automatically downloading packages and resolving their dependencies from the repositories defined in /etc/apt/sources.list.

  17. What are package dependencies? Explain with an example.
    Topic: Ubuntu Server and Package Management

    Dependencies are additional packages required by a principal package in order to function properly. Many complex packages use dependencies, and for the package to function, it and all of its dependencies must be installed. For example, the speech synthesis package 'festival' depends upon the package 'libasound2', which supplies the ALSA sound library needed for audio playback; festival cannot work until libasound2 is also installed. The software management tools in Ubuntu handle dependencies automatically.

  18. Differentiate between a primary group and a secondary group. In which files is group information stored?
    Topic: User Management and Security

    Every user is a member of at least one group, called the user's primary group; any additional groups a user belongs to are called secondary groups. The most important difference appears when a user creates a new file: the file's group ownership is set to the user's primary group. Group membership can be displayed with the 'id' or 'groups' command. Group-related information is stored in several files: /etc/passwd contains user account information including the primary group membership of each user; /etc/group stores information about each group, including the group name, group ID (GID) and secondary user membership; and /etc/gshadow stores additional group information, including group administrators and the group password.

  19. Write the Ubuntu commands to add a user, delete a user, and to lock and unlock a user account.
    Topic: User Management and Security

    Add a user: 'sudo adduser username' - follow the prompts to give the account a password and identifiable characteristics. Delete a user: 'sudo deluser username' - this deletes the user account and its primary group (note that deleting an account does not remove the user's home folder). Lock a user account: 'sudo passwd -l username'. Unlock a user account: 'sudo passwd -u username'.

  20. Why does locking a user account not completely prevent that user from logging into a server remotely? What should the administrator check?
    Topic: User Management and Security

    Simply disabling or locking a user account will not prevent the user from logging into the server remotely if they have previously set up RSA public key authentication, because they can still gain shell access through SSH without needing any password. The administrator should check the user's home directory for files that allow this type of authenticated SSH access, e.g. /home/username/.ssh/authorized_keys, and remove or rename the .ssh directory to prevent further SSH authentication. The administrator should also check for any established SSH connections by the disabled user and kill them, and can restrict SSH access to only required accounts using the AllowGroups variable in /etc/ssh/sshd_config.

  21. What is OpenSSH? Why is it preferred over traditional tools like telnet and rcp?
    Topic: Remote Administration and Logging

    OpenSSH is a freely available version of the Secure Shell (SSH) protocol family of tools for remotely controlling, or transferring files between, networked computers. It provides a server daemon (sshd) and client tools to facilitate secure, encrypted remote control and file transfer operations. Traditional tools used for these functions, such as telnet or rcp, are insecure because they transmit the user's password in cleartext when used; OpenSSH effectively replaces these legacy tools by encrypting the communication. OpenSSH can use many authentication methods, including plain password, public key and Kerberos tickets.

  22. Explain the working of Puppet in a client-server configuration.
    Topic: Remote Administration and Logging

    Puppet is a cross-platform framework that enables system administrators to perform common tasks using code, from installing new software to checking file permissions or updating user accounts. It uses a client-server approach consisting of the Puppet Master - a server running the Puppet Master daemon that manages crucial system information for all nodes using manifests - and Puppet Agents, the nodes with the Puppet Agent daemon running. The agents use pull mode to poll the master and retrieve configuration information. The working steps are: (1) a node running the Puppet Agent gathers all information (facts) about itself and sends the facts to the Puppet Master; (2) the Puppet Master uses this data to create a catalog describing how the node should be configured and sends it back to the agent; (3) the Puppet Agent configures itself based on the catalog and reports back to the Puppet Master.

  23. Differentiate between kernel logging and user logging.
    Topic: Remote Administration and Logging

    On Linux there are two types of logging mechanisms. Kernel logging is related to errors, warnings or information entries that the kernel may write; it is done via the kernel ring buffer, a circular buffer that is the first data structure storing log messages when the system boots up, and kernel logging is started before user logging. Kernel logs can be inspected with the 'dmesg' command; examples of events are errors in mounting a disk and driver loading. User logging is linked to the user space; those log entries are related to processes or services that run on the host machine, and are handled by tools such as syslogd and systemd-journal, with log files stored under /var/log.

  24. What is log rotation? Why is it needed, and which tool performs it?
    Topic: Remote Administration and Logging

    Log rotation is the process in which old log files are automatically renamed after a predefined time-frame and a new original log file is started; after even more time, the rotated log files are compressed with the gzip utility (for example, daemon.log.1.gz). The purpose of log rotation is to archive and compress old logs so that they consume less disk space, but are still available for inspection as needed. It is performed by the logrotate utility, which is called from the system-wide cron script /etc/cron.daily/logrotate and is configured through /etc/logrotate.conf and individual configuration files in /etc/logrotate.d.

  25. Explain any five special variables used in shell scripting.
    Topic: Shell Scripting

    Special variables in shell scripting include: (1) $0 - the filename of the current script. (2) $n - the arguments with which a script was invoked, where n is the position of the argument ($1, $2, ...). (3) $# - the number of arguments supplied to a script. (4) $* - all the arguments, double quoted as a single string. (5) $@ - all the arguments, individually double quoted. (6) $? - the exit status of the last command executed. (7) $$ - the process number (PID) of the current shell. (8) $! - the process number of the last background command.

  26. Differentiate between the while loop and the until loop in shell scripting.
    Topic: Shell Scripting

    The while loop executes its statements repeatedly as long as its command (condition) is true; the loop stops when the command becomes false, so it is used when the statements should run while a condition holds. The until loop is the opposite: it executes its statements until the command becomes true, i.e. it keeps running while the condition is false and stops as soon as the condition becomes true. Both loops are used for repetitive tasks, but they differ in the condition logic that controls them.

  27. Compare direct-attached storage (DAS), network-attached storage (NAS) and storage area network (SAN).
    Topic: Server Hardware and Storage

    DAS (Direct-Attached Storage) is storage connected directly to the server with SAS, SATA or PCIe, e.g. HDDs, SSDs and NVMe SSDs in the server itself; it is cheap and simple. NAS (Network-Attached Storage) provides access to the same data on multiple systems over the network; it can be very fast and very high capacity, can mix SSDs and hard drives, and always uses RAID storage, but it requires a separate computer and is expensive. SAN (Storage Area Network) is used for sophisticated databases, virtualization deployments, large virtual desktop infrastructures (VDIs) and enterprise resource management workloads; it is resilient and removes single points of failure, easily withstanding failure of multiple components/devices, but it is expensive and complex.

  28. What is RAID? Explain RAID 0, RAID 1 and RAID 5.
    Topic: Server Hardware and Storage

    RAID (Redundant Array of Independent Disks) is a way of storing the same data in different places on multiple hard disks or solid-state drives (SSDs) to protect data in case of a drive failure; however, not all RAID levels have the goal of providing redundancy. RAID 0 stripes data blocks across two or more disks for performance, but provides no redundancy - if one disk fails, data is lost. RAID 1 mirrors the same data on two disks, so if one disk fails the other still has a complete copy. RAID 5 stripes data across disks together with distributed parity blocks, so the data can be recovered if a single disk fails.

  29. What is horizontal scaling? How is it different from vertical scaling?
    Topic: Server Hardware and Storage

    As demand on a running service grows, the service must be scaled to handle the larger workload. Horizontal scaling (scaling out) means adding more machines or servers to the system so that the workload is shared among them - for example, adding more identical servers behind the existing service, similar to the grid approach in which many machines are managed as one unit. Vertical scaling (scaling up) means increasing the capacity of the existing machine itself, for example by adding a faster CPU, more RAM or more storage to the same server. Horizontal scaling can keep growing by adding machines and also improves resilience, while vertical scaling is limited by the maximum capacity of a single machine.

  30. What is out-of-band (OOB) management? Why must OOB interfaces be isolated from the main network?
    Topic: Server Hardware and Storage

    Out-of-band (OOB) management is the remote management capability built into modern servers (such as iLO - Integrated Lights-Out, and IPMI), which provides an Ethernet interface through which the remote system console can be accessed via a browser or client, even when the main system is down or powered off. OOB interfaces must be isolated from the main network and placed on a dedicated protected network because an OOB interface is equivalent to physical access to the machine: anyone who compromises it gains complete control of the server. Built-in systems have also been found to suffer from traditional security holes such as buffer overruns, so a password and SSL alone are not sufficient protection; a web proxy, authentication and authorization should also be used.
