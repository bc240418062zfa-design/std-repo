                            CS401 – Preface

1. What is Assembly Language?

 A programming language that talks directly to the computer.
 In high-level languages (like C, C++, Java), there is a “gap” between the
  programmer and the machine.
 This gap is filled by compilers or interpreters, but in assembly, you bypass most
  of them.
 It works close to hardware, giving you more control.

2. Is it difficult?

 People think it’s hard, but it’s actually simple.
 It looks hard because we are used to thinking computers are complicated.
 Assembly is just direct and clear — what you write is exactly what the computer
  does.

3. Course focus

 Examples will use IBM PC with Intel processors.
 Concepts will be platform-independent (can work on any system).

Basic knowledge needed:

1. Digital logic (AND, OR, NOT)
2. Binary numbers and arithmetic

4. Why learn Assembly?

Optimization: Makes code faster by removing unnecessary instructions.

Real-time systems: Needed when operations must finish in a fixed time.
Fine control: You control each instruction — no hidden steps like in “for” loops in
high-level languages.

5. When to use it?

 In performance-critical parts of a program (e.g., image processing).
 To make programs run faster by saving CPU cycles.
 To meet exact timing requirements in hardware control systems.

6. How to learn it?

 You can’t just read; you must practice.
 Try every example, run code, test, and experiment.
 Only by doing this will you see how powerful and simple it is.

                          Chapter 1
             Introduction to Assembly Language
1.1. BASIC COMPUTER ARCHITECTURE

1. Computer main parts:

1. Processor (CPU) – Does the operations.
2. Memory (RAM) – Stores data.
3. I/O devices – Connects computer to outside world (keyboard, display, etc.).

For now, we focus only on Processor + Memory.

2. Communication between CPU & Memory

To work, CPU must:

 Know which data to read/write.
 Tell memory whether to read or write.
 Actually transfer the data.

This is done via 3 types of buses:

       Bus                      Purpose                            Direction
   Address Bus Sends memory address (location) to access. Unidirectional (CPU → Memory)
    Data Bus   Transfers actual data between CPU & Memory.       Bidirectional

      Bus                        Purpose                            Direction
   Control Bus Sends control signals (read/write, status info).   Bidirectional

3. How each bus works

Address Bus

 Tells memory exactly which cell to use (like giving an address to a postman).
 Always one-way from CPU to Memory.
 Example: “Fifth book from top” = specific memory location.
 Memory cell size is called cell width (often 8-bit = 1 byte).

Data Bus

 Transfers actual data.
 Can go both directions:
                                  1. CPU → Memory (write)
                                  2. Memory → CPU (read)

Control Bus

Sends read/write commands and special status signals.
Also lets peripherals send “status” back to CPU (e.g., “door locked” message).
Ensures synchronization — CPU reads when memory is ready, writes when memory
can accept.

4. Why synchronization is important

 If CPU wants to read but memory is trying to write → No communication happens.
 Control bus ensures CPU and memory act in correct order (one speaks, one listens).

1.2 Registers

What are Registers?

 Tiny, super-fast storage areas inside the CPU.
 Used to hold data (operands) temporarily while processing.
 Faster than main memory.
 Very few in number → precious resource.

Why do we need Registers?

 CPU can get only one data item at a time from memory via the data bus.

 But most operations (like addition) need two operands.

Solution:

 Store one operand in a register.
 Bring the second operand from memory.
 Perform operation quickly.
 Sometimes both operands are in registers for maximum speed.

Registers vs Memory

                         Registers                Memory
                         Very fast                  Slower
                      Few in number               Large size
                        Inside CPU               Outside CPU
                        Expensive                  Cheaper

Types of Registers

1. Accumulator

 Main register for math & logic operations.
 Width of accumulator = CPU word size
 (e.g., 32-bit CPU → 32-bit accumulator).

2. Pointer / Index / Base Register

 Holds address of data (not the data itself).
 Useful in loops & arrays (e.g., accessing each element in order).
 Changes automatically in repetitive tasks.

3. Flags Register (Program Status Word)

 Stores status bits after operations.
 Each bit has its own meaning (not combined).
 Example: Carry Flag stores extra bit after addition overflow.

4. Program Counter / Instruction Pointer

 Holds address of next instruction to execute.
 Moves step-by-step through the program.
 CPU understands numbers (opcodes), not words like "ADD".

 Mnemonics (e.g., ADD A, B) are symbolic forms → converted by Assembler into
  opcodes.

1.3 Instruction Groups

What are Instruction Groups?

Every processor has a set of opcodes for:

   Moving data
   Doing math & logic
   Controlling program flow
   Special tasks

Mnemonics (human-readable names for opcodes) vary by manufacturer:
One CPU may use MOV, another may use LOAD or STORE.
Basic idea is same → only names differ.
Grouping instructions makes it easy to learn a new processor.

Main Instruction Groups

1. Data Movement Instructions

Purpose: Move data from one place to another.

Sources/Destinations can be:

1. Registers
2. Memory
3. Peripheral devices

Examples:

mov ax, bx → Copy data from bx to ax.
lad 1234 → Load data from address 1234 into a register.

Key point: Only moves data, doesn’t change it.

2. Arithmetic and Logic Instructions

Arithmetic → Add, subtract, multiply, divide.
Logic → AND, OR, XOR, NOT (complement).
