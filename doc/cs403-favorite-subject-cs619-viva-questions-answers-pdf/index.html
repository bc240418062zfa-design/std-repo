What is normalization?
Normalization in database management is a process of organizing the data in a relational
database to reduce data redundancy and improve data integrity. The main goal of normalization
is to structure the database schema in such a way that it minimizes data duplication and ensures
that data is stored efficiently and accurately.
Normalization is typically applied to relational databases, where data is organized into tables
with rows and columns. It is based on a set of rules or guidelines, known as normal forms,
which help ensure that the data is free from anomalies such as insertion, update, and deletion
anomalies. The most commonly used normal forms are:

1. First Normal Form (1NF): Ensures that each column in a table contains only atomic
(indivisible) values, and there are no repeating groups or arrays.

2. Second Normal Form (2NF): Extends 1NF by ensuring that non-key attributes are fully
functionally dependent on the primary key. In other words, it eliminates partial dependencies.

3. Third Normal Form (3NF): Extends 2NF by removing transitive dependencies, where non-
key attributes are dependent on other non-key attributes rather than the primary key.

There are higher normal forms beyond 3NF, such as Boyce-Codd Normal Form (BCNF) and
Fourth Normal Form (4NF), which deal with more complex scenarios and dependencies.

The process of normalization involves decomposing tables into smaller ones, creating
relationships between them using foreign keys, and ensuring that data is stored in a way that

What is 2nd normal form?
A relation is in second normal form (2NF) if and only if it is in first normal form and all the non-
key attributes are fully functionally dependent on the key. Clearly, if a relation is in 1NF and the
key consists of a single attribute, the relation is automatically in 2NF. The only time we have to
be concerned about 2NF is when the key is composite. Second normal form (2NF) addresses the
concept of removing duplicative data. It removes subsets of data that apply to multiple rows of a
table and place them in separate tables. It creates relationships between these new tables and
their predecessors through the use of foreign keys.
What is 3rd normal form?
A relational table is in third normal form (3NF) if it is already in 2NF and every non-key column
is non-transitively dependent upon its primary key. In other words, all non-key attributes are
functionally dependent only upon the primary key. The primary focus of 3NF is to eliminate
transitive dependencies. A transitive dependency occurs when a non-key attribute depends on
another non-key attribute, rather than directly on the primary key.
In which normal form we use functional dependency?
Functional dependency is a concept that applies to various normal forms in the database
normalization process. It is a fundamental concept used to describe how attributes (or columns)
in a relation (or table) depend on other attributes within that relation. Functional dependencies
are used to help identify and achieve higher normal forms, including the Second Normal Form
(2NF), Third Normal Form (3NF), Boyce-Codd Normal Form (BCNF), and Fourth Normal Form
(4NF).

Here's how functional dependencies relate to these normal forms:

1. Second Normal Form (2NF): In 2NF, functional dependency is used to eliminate partial
dependencies. A functional dependency specifies that one attribute is functionally dependent on
another within the same relation. To achieve 2NF, you need to ensure that non-prime attributes
(attributes not part of the primary key) are fully functionally dependent on the entire primary
key.

2. Third Normal Form (3NF): In 3NF, functional dependency is used to eliminate transitive
dependencies. Functional dependency specifies that one attribute is functionally dependent on
another, and in 3NF, you ensure that non-key attributes depend only on the primary key and not
on other non-key attributes.

3. Boyce-Codd Normal Form (BCNF): BCNF is an advanced form of normalization that deals
with functional dependencies and ensures that a relation is in 3NF and that for every non-trivial
functional dependency (where an attribute determines another non-prime attribute), the left-hand
side of the dependency is a superkey (a set of attributes that uniquely identifies a tuple).

4. Fourth Normal Form (4NF): 4NF deals with multi-valued dependencies, which are a type of
functional dependency. It ensures that a relation is in BCNF and that there are no non-trivial
multi-valued dependencies.

Functional dependencies play a critical role in helping database designers understand and model
the relationships between attributes in a database schema. By analyzing functional dependencies,
designers can make informed decisions about how to normalize the schema to reduce data
redundancy and maintain data integrity.
Define Transitive dependency?
A transitive dependency is a concept in the field of database management and normalization
theory that describes a specific type of functional dependency between attributes (or columns)
within a relational database table. In a transitive dependency, the value of one non-key attribute
(or column) in a table depends on another non-key attribute through a chain of dependencies.
