2. WBS: Work, Benefits, and Related Concepts

Benefits of WBS:

      Defines 100% of the work per scope.
      Helps manage cost, schedule, and responsibilities.
      Tracks progress and aids in communication with stakeholders.
      Serves as a budgeting and reporting tool.
      Allows for task delegation and control over time

By Maha Rana

Characteristics of High-Quality WBS:

       Hierarchical and logical structure.
       Must receive team buy-in.
       Deliverable-oriented and clear.
       Should be in sync with scope and project plan.
       Updated regularly to reflect current status.

WBS Conceptual:

       A functional decomposition of the entire project.
       Bridges between project scope and schedule.
       Includes all deliverables, internal/external/interim.
       Produced after the scope statement but before detailed scheduling.

✅1. Initial Estimates – Formula + Example
Formula for Initial Estimation (Effort):

Effort = a₁ × (SLOC/1000)^a₂ × EAF

By Maha Rana

Where:

        a₁ and a₂ are project-type constants (organic, semi-detached, embedded)
        SLOC = Source Lines of Code
        EAF = Effort Adjustment Factor (from cost drivers)
         This formula is from Intermediate COCOMO Model.

Example (Assume values from the question):

        SLOC = 32,000 → KDSI = 32
        a₁ = 3.0
        a₂ = 1.12
        EAF = 1.15

Effort = 3.0 × (32)^1.12 × 1.15 = ~147 person-months

✅5. Primary Planning Tasks
Planning tasks in software project management include:

   1.   Scope Definition – What the project must achieve.
   2.   Task Scheduling – Breaking down deliverables into WBS.
   3.   Effort and Cost Estimation – Using models like COCOMO.
   4.   Resource Allocation – Assigning tools, people, budget.
   5.   Risk Management – Identify and plan for potential failures.

6. Categories in Typical WBS
Typical WBS (Work Breakdown Structure) includes these categories:

   1.   Project Management – Coordination, reporting, meetings.
   2.   Product Requirements and Design – Analysis and architecture.
   3.   Implementation – Coding, unit testing.
   4.   Integration and Testing – System testing, bug fixing.
   5.   Deployment and Maintenance – Final delivery, support.
   6.   Documentation and Training – Manuals, user training.
