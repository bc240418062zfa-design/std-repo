Question?
Suppose you are working as a developer in a conventional university. Anticipating the increasing number of admissions, the university decided to upgrade its manual library management system to an automated online library management system. New categories may also be introduced, and new policies will incorporated frequently. be

As a web developer, you are tasked with designing an online library system using object-oriented modelling. The system should allow users to browse books, check their availability, borrow and return books, and provide recommendations based on users" preferences. You have to choose one of the following object-oriented modelling approaches and justify your answer with proper reasoning.

a) Inheritance-Based Approach

b) Composition-Based Approach

Answer.
In this scenario, I would recommend using the Composition-Based Approach for designing the online library system.

Composition is a fundamental principle of object-oriented programming that allows for building complex objects by combining simpler objects together. It involves creating objects that are composed of other objects, forming a "has-a" relationship rather than an "is-a" relationship as in inheritance.

Here are the reasons for choosing the Composition-Based Approach:

1. Flexibility and Modularity: Composition allows for greater flexibility and modularity in the design of the online library system. With composition, we can create smaller, reusable objects that can be easily combined to form more complex objects. This modular approach makes it easier to modify or extend the system in the future as new categories or policies are introduced. It also allows for better code organization and maintainability.

2. Encapsulation and Information Hiding: Composition promotes encapsulation and information hiding, which are important principles in object-oriented design. Each object encapsulates its own behavior and data, and the internal details of an object are hidden from other objects. This allows for better control over the system's functionality and reduces dependencies between objects. It also enhances code reusability and helps in maintaining a clear separation of concerns.

3. Better Representation of Real-World Relationships: Composition models real-world relationships more accurately hothan inheritance in many cases. In a library system, books can be represented as individual objects, and other objects like users, preferences, availability, and recommendations can be composed together to form a cohesive system. This approach aligns well with the natural relationships and interactions between different entities in a library environment.

4. Easy Adaptation to Changing Requirements: The Composition-Based Approach is well-suited for handling changing requirements and introducing new features. Since objects are loosely coupled, modifications can be made to individual components without affecting the entire system. This makes it easier to incorporate new categories, update policies, or add new functionalities to the online library system without extensive modifications to the existing codebase.

Overall, the Composition-Based Approach provides a more flexible, modular, and adaptable design for the online library system. It promotes code reusability, encapsulation, and better representation of real-world relationships. These factors make it a suitable choice for building a scalable and maintainable library management system in a conventional university setting.
