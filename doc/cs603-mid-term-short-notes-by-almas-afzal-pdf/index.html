                                    Topic_1
                              Design (What & Why)

What is Design?
Design can be defined by two ways:
 As a Verb
 As a Noun

As a Verb: It is defined to make draw plans from something, for examples Clothes or
buildings.
As a Noun: It is defined as a drawing or sets of drawings showing how a building or product
is to be made and how it will work and look.

What is Software Design?
Software Design is the process of defining the architecture, components, modules, interfaces,
and data for a software system to satisfy specified requirements. It acts as a blueprint for
software development and ensures that the system is structured, maintainable, and efficient.

It includes design principles, patterns, and methodologies to create high-quality software

Why do we use Design?
We design things to improve situations, solve problems ans explore alternatives.

                                 Topic_2
                       Software Design (Objectives)

1. System Specification
System specification defines what the software should do.

It includes:

 Functional & Non-functional Requirement
 User Needs & Constraints
 Hardware & Software Requirements

2. The Software Design Process
The software design process is a structured approach that includes:

      Requirement Analysis – Understanding what the system should do.

      Architectural Design – Defining the system’s high-level structure.

      Detailed Design – Designing individual components/modules.

      Validation & Verification – Checking the design to avoid errors.

3. A Blueprint For implementation
Software design acts as a blueprint (plan) that guides developers.

It includes:

      Diagrams (UML, Flowcharts) to visualize system components.

      Architecture patterns (MVC, Layered Architecture) to organize code.

      Coding standards & guidelines to ensure quality.

During the design phase , software engineers apply their knowledge of:
 The problem domain
 Implementation Technologies

Basic Objectives of Software Design:
 It translates system specification into plans for the technical implementation of the
  software.
 It serves as a technical plan for implementation.
 It specifies the overall structure and organization of the eventual code.

The system or Program should meets the customer’s needs.

A Software Should be:
 Easy to Implement
 Efficient
 Easily Extendible to meet new needs

                             Topic_3 & 4
                  Software Design (Complexity & Size)

Remember that:
Poorly designed programs are difficult to understand & Modify.

Software design complexity refers to how difficult it is to understand, modify, test, or
maintain a software system. It depends on:

Code Structure – Messy or well-organized?
Module Interactions – Are components highly dependent on each other?
Algorithms & Logic – Are they simple or too complex?
Scalability – Can it handle growth easily?

Example: A simple calculator app has low complexity, while an AI-based chatbot has
high complexity due to advanced algorithms.

Software Design Size:
Software size refers to the amount of code, number of modules, and overall system scope.
It is measured using:

Lines of Code (LOC) – Total number of written code lines.
Function Points (FP) – Measures functionality based on inputs, outputs, and interactions.
Cyclomatic Complexity – Measures the number of independent paths in the code.

Impact of Size:
      Small-sized software is easier to develop and maintain.

      Large-sized software requires careful planning, modularity, and documentation.

                              Topic_5
               Software Design (types of Complexities)

1. Essential Complexities
Complexities that are inherit in the problem.

2. Accidental / incidental Complexities
Complexities that are artifacts of the Solution.

The total amount of complexity in a software design is:
Essential Complexities + Accidental / incidental Complexities

Design: is an Antidote to complexity

Design is a primary tool for managing essential & accidental complexities in Software.

                                  Topic_6
                       Why is Software Design Hard?

Why is Software Design Hard?
Software Design is hard because design is an abstraction of the solution which has yet to be
created.

                                     Topic_7
                                 Software Design
                               A science or an art?

Software design is considered both a science and an art because it involves structured
principles (science) and creative problem-solving (art).

 Software design is a science because it follows engineering principles.
 It is also an art because it requires creativity and problem-solving skills.
 The best software designs balance both aspects for efficiency and user satisfaction.

MCQ:

         Science is a repeatable process.
         For Example: 2 + 2 = 4

                               Topic_8
                  Software Design (A Wicked Problem)

A Wicked Problem
A problem that can only be clearly defined by completely solved it.

Software design is not just a step-by-step process; it requires continuous adaptation,
problem-solving, and decision-making. Since there is no perfect solution, designers must
focus on flexibility, scalability, and maintainability.
